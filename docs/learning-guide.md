# 미디님의 첫 학습 순서

## 1. 코드를 바꾸기 전에
README의 BM25 실행 명령을 실행하고 results.json의 질문 하나를 읽습니다.
gold는 정답, ranked는 검색 결과 순서입니다.
정답이 2번째에 있으면 MRR은 1/2이라는 것을 직접 확인합니다.

## 2. 데이터 읽기
q01과 정답 문서 unemployment-seoul24를 찾아 비교합니다.
같은 주제의 부산 문서와 2023년 문서는 왜 정답이 아닌지 설명합니다.
q03은 왜 정답이 2개인지 확인합니다.

## 3. 첫 직접 변경
dev 질문의 실패 원인을 먼저 적습니다.
토큰화 한 부분만 바꿔 새 결과 폴더에 실행하고 전후 표를 작성합니다.
점수가 내려가도 실패한 이유를 남기면 유효한 실험입니다.

## 4. 면접 설명 연습
- 왜 임베딩 검색이 항상 키워드 검색보다 낫다고 가정하면 안 될까?
- 리랭커는 후보 검색에서 놓친 문서를 찾을 수 있을까?
- 정답이 없는 질문을 Recall=0으로 섞지 않는 이유는?
- 합성 데이터 결과를 실제 서비스 성능이라고 말할 수 없는 이유는?

초기 구현은 AI 도움을 받았다고 밝히고, 직접 읽고 변경·검증한 범위를 구체적으로 설명합니다.
